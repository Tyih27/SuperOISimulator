# 审计报告：数值平衡性

本篇量化评估战斗数值、养成经济与竞技场数值。所有实验均为只读内存模拟，直接复用游戏真实代码路径（`createProfile → createBattleSnapshot → CombatEngine.fromSnapshot().run()`），与玩家实际体验一致。

---

## 1. 【P0】主线关卡不可战胜，进度死锁

### 1.1 官方基线本身就承认 0% 胜率

`src/data.js:227-232` 的 `BALANCE_BASELINES` 与 `docs/BALANCE_BASELINE.md` 批准的胜率：

| 关卡 | 批准胜率 | 目标 |
| --- | ---: | --- |
| chapter-1-1 | **0.00%** | 12 回合内通过 3/8 题 |
| chapter-1-2 | 5.83% | 14 回合内通过 3/5 题 |
| chapter-1-3 | **0.00%** | 16 回合内通过 4/4 题（全部） |
| chapter-1-4 | **0.00%** | 18 回合内通过 8/8 题（全部） |

平衡门槛测试（`npm run test:balance`）把这套数字固化为" approved"，即**测试在保护一个不可通关的游戏**。新账号仅解锁 chapter-1-1，因此进度在第一关就死锁——chapter-1-2 的 5.83% 对新玩家毫无意义。

### 1.2 真实新号实测（本次审计新增验证）

用与线上完全一致的路径模拟 20 个随机新号（能力值按普通资质区间随机掷取，如 planner 实测得到 DP 562 / 图论 476 / 数据结构 609 / 数学 407 / 实现 891）：

```
chapter-1-1，默认编队 planner/graphist/structurer：
胜率 0 / 20；平均完成题目 2.00 / 3；平均用时 11.9 / 12 回合
```

差距是结构性的：每名学生对单题的基准进度约 900～1250，一题需要 10000 进度 ≈ 8～11 次行动；三名学生每回合共 3 次行动，12 回合共 36 次行动，理论上限刚好够 3 题——但目标规则会把攻击分散到不同题目、爆发技能会偏转目标、学生中途退场还会跳过行动，实际稳定停在 2 题。

### 1.3 通关成本阶梯实验

对初始能力做定向强化后重测（每次训练 = +40 能力，见 §4）：

| 投入 | 训练次数 | 训练币（不含书）| 胜率 |
| --- | ---: | ---: | --- |
| 每人主能力+实现 各 +320 | 48 次 | 4,800 | **0 / 3** |
| 定向加强版（部分人练 3 项） | 64 次 | 6,400 | 1 / 3 |
| 全队 15 项能力全部 +320 | 120 次 | 12,000 | **5 / 5** |

**结论**：稳定通关第一章第一关需要约 64～120 次训练。这不是"新手关"，这是一堵墙。

## 2. 战斗公式评估：攻防严重失衡

公式本身（`src/combat/math.js`）与设计文档一致，问题在参数配比：

### 2.1 进度端（我方输出）

```
基准进度 = clamp(1000 + 平均能力差 × 2, 100, 2000)
```

普通资质学生（450~650）对阵 800~940 难度的题目，能力差约 -150~0，基准进度落在 700~1000。完成一题需 10~14 次行动。

### 2.2 伤害端（题目反击）

```
精力伤害 = clamp(500 + 平均短板 × 2, 100, 2000)
```

实测典型新号学生被三道初始题攻击的伤害为 **659 / 796 / 771**，三题齐射 ≈ **2,200/回合**；全队总精力约 15,600，无治疗约 7 回合团灭。而 structurer 单体治疗实测仅 **≈813/次**、群体爆发 ≈1,000/人——治疗量不足伤害的 40%。

### 2.3 结构性矛盾

- 学生越弱 → 短板越大 → 承伤越高 → 更早退场 → 行动次数更少 → 进度更低。**弱者遭受双重惩罚**，且没有保底机制打破循环。
- 专注爆发（5 回合一次 ×1.25~1.6 倍）远不足以弥补 30%~50% 的基础输出缺口。
- 设计文档 §5.1 说"能力低于难度时仍然可以推进，但速度更慢"，实际参数让"更慢"直接等于"不可能"。

## 3. 【P1】平衡模拟工具失真，基线不代表真实游戏

`scripts/simulate-formations.js:64`：

```js
students: teamIds.map((studentId) => studentById.get(studentId)),
```

直接使用 `src/data.js:161-210` 中学生的**固定展示数值**（planner DP=820、mathematician 数学=920 等）。但真实玩家的初始六名学生由 `createOwnedStudent → generateInitialAbilities`（`src/domain/profile.js:49-66`、`src/domain/student-identity.js:62-70`）在普通资质区间内**随机掷出**，数据文件里的 `abilities` 字段根本不进入玩家档案。

后果：

1. 基线 600 局模拟用的是一支比任何真实玩家都强的虚构队伍，**真实胜率低于基线**（基线已是 0%，真实同样是 0%，但 chapter-1-2 类"勉强能赢"的关卡会被系统性高估）；
2. `data.js` 中 `STUDENTS[].abilities` 成为误导性死数据——它既不用于生成档案，也不用于战斗快照；
3. 平衡门槛测试给出虚假安全感。

**修复建议**：模拟脚本改为 `createProfile()` 生成 roster（可固定 identitySeed 保证可复现），并重新校准基线。

## 4. 养成经济测算：收入与支出严重错配

### 4.1 收入来源

| 来源 | 数额 | 条件 |
| --- | ---: | --- |
| 每日签到 | 1,000 训练币 | 每日 1 次（UTC 重置，见 BUG-07）|
| 主线奖励 | 100~260 币 + 训练册 | **当前不可获得**（0% 胜率）|
| 竞技场进攻胜利 | 25 训练币 | 需要存在其他玩家防守编队 |
| 初始资产 | 1,000 币 + 1 招募券 | 仅一次 |

### 4.2 支出与瓶颈

每次专项训练 = 100 训练币 + 1 本对应训练册或培养材料（`src/domain/progression.js:13-15`）：

| 道具 | 价格 | 限购 |
| --- | ---: | --- |
| 数据结构/数学/实现训练册 | 100 币 | 无限购 |
| 动态规划/图论训练册 | 120 币 | **每日 1 本** |
| 学生培养材料 | 无法购买 | 仅劝退招募学生获得（每名 +1）|
| 招募权（→券） | 300 币 | 无限购 |

按 §1.3 的 120 次训练估算首关通关成本：

- 训练币：120 × 100 = **12,000**
- 训练册：120 本。DP/图论册每日限购 1 本迫使玩家要么等天数、要么用无限购的其他册替代（但对应能力必须喝对应册）→ 实际上 DP/图论能力的训练速度被硬性限制在 **每天 1 次**（材料路线除外，而材料只能靠 300 币/张的招募券转化，每张券仅换 1 份材料）
- 以纯签到收入计：**12,000 ÷ 1,000 = 12 天起**，叠加限购约束后现实周期 **约 2 周**

而这是四关中的第一关；chapter-1-3/1-4 要求全部通过且难度更高（数学 860~900 等），投入只会更大。

### 4.3 【P1】主线奖励可无限刷取（与 4.2 叠加后的经济漏洞）

`server/services/battle-service.js:86-185`：每次 `start` 生成新 `battleId`，`settle` 胜利即发全额奖励，**没有"每关仅首次"的限制**。幂等表 `campaign_settlements` 只服务于无人调用的死代码路径（BUG-12）。

一旦玩家跨过 §1 的门槛，即可反复开打已通关卡：chapter-1-1 每场 100 币 + 1 本 DP 册，数分钟一轮，签到经济的全部设计瞬间失效。当前因为游戏打不过而漏洞未暴露，属于"修好平衡后立刻会引爆"的延迟炸弹。

**修复建议**：发奖引入每关首次通关全额、重复通关小额（如 20%）的递减结构，并把幂等键从 battleId 改为 (accountId, levelId, firstClear)。

## 5. 竞技场数值评估

| 项目 | 现状 | 评估 |
| --- | --- | --- |
| 题池 | 固定 chapter-1-1（`server/services/arena-service.js:13`）| 与主线练度完全脱钩：高练度恒胜、低练度恒败，无策略空间 |
| 积分 | 固定 ±25，防御方被动扣/加，下限 0 | 无段位曲线；0 下限造成底部通缩 |
| 奖励 | 进攻胜利 25 币，失败/平局 0 | 相对 300 币/张招募权性价比极低 |
| 对手发现 | 积分最接近的前 10 名（`server/repositories/arena-repository.js:23`）| 无分页；服务器人数少时列表为空，竞技场整体不可用 |
| 胜负判定 | 胜场 > 完成题数 > 剩余精力（`src/combat/arena-engine.js:24-36`）| 缺失设计文档 §6.4 要求的两级 tiebreak（未通过题完成率之和 → 最后行动阶段），同分时提前判平局 |
| 防守语义 | 双方各自独立打镜像题，互不干涉 | 符合"异步镜像"设计，但"防守编队"实际只贡献一个比分，命名易误导 |

## 6. 文档与代码的数值漂移对照表

| 项目 | docs/GAME_DESIGN.md | 实际代码 | 影响 |
| --- | --- | --- | --- |
| 普通资质区间 | DP 400~700 / 图论 400~700 / DS 400~700 / 数学 350~600 / 实现 700~950（§2.1 表）| `src/data.js:41`：DP 450~650 / 图论 450~650 / DS 500~700 / 数学 350~550 / 实现 **800~1000** | 文档承诺的能力面更宽；实现收窄后数学上限更低，加剧 §2 的输出缺口 |
| 成长上限 | "成长后允许超过该范围，不设置全局硬上限"（§2.1）| `MAX_TRAINED_ABILITY = 2_000` 硬上限（`src/domain/progression.js:15`）| 长线养成天花板与文档相悖 |
| 多人平局判定 | 完成题数 → 未通过题完成率之和 → 剩余精力 → 最后行动阶段（§6.4 四级）| 仅实现三级中的 1、3 级（`arena-engine.js:29-35`）| 同分场景判定与文档不符 |
| 顶尖资质区间 | 700~1100 / 750~1150（§2.1）| `src/data.js:53` 全部 800~1000 | 招募高端学生的实际强度低于文档描述 |
| 竞赛币/竞赛商店/排行榜 | §7.4、§8.4 承诺随首个异步多人版本加入 | 竞技场已上线但三者均不存在 | 见 AUDIT_FEATURES §5 |

> 注：GAME_DESIGN §2.1 自称"表格是可配置参数"，允许实现微调；但区间形状（尤其实现能力 700~950 vs 800~1000、数学上限 600 vs 550）直接影响关卡可行性，应回写文档保持一致。

## 7. 调参方向建议（供决策，非唯一解）

目标是把 chapter-1-1 对**零训练新号**的胜率调到 40%~60%，同时保留成长价值。以下选项可组合，均只需改数据不改引擎：

1. **降低首关题目难度**（推荐）：把 chapter-1-1 题池中 800+ 的难度降到 650~750，或为首关单独配置一组低难题目。改动最小、语义最直白。
2. **提高进度系数**：`calculateBaselineProgress` 的 `× 2` 提到 `× 2.5~3`，或把基准 1000 提到 1100。全局生效，需同步复核后续关卡。
3. **降低反击伤害基数**：`calculateEnergyDamage` 的 500 → 350，或短板系数 ×2 → ×1.5。缓解"弱者双罚"，但对关卡时限帮助有限。
4. **提高 maxProgress 之外的杠杆**：把首关目标从 3 题降为 2 题（`requiredTopics: 2`）。最保守，几乎必然可通。
5. **配套经济修复**（无论选哪项都建议做）：
   - 主线奖励改为首次全额 + 重复递减（堵 §4.3 漏洞）；
   - DP/图论训练册取消每日限购或增设第二档高价不限购版本；
   - 商店增加"学生培养材料"直售（如 150 币/份），打通非酋材料来源；
   - 签到重置改为本地时区语义（配合 BUG-07）。

调整后务必：更新 `BALANCE_BASELINES` 与 `docs/BALANCE_BASELINE.md`，并先按 §3 修复模拟工具的数据源，否则门槛测试将继续保护错误数值。
