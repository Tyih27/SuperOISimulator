# Task 11 Asynchronous Arena Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic asynchronous arena battles with immutable defense snapshots, rating settlement, opponent discovery, and read-only replay.

**Architecture:** Reuse `CombatEngine` snapshots as the per-side combat kernel, while `runArena` coordinates paired A/B stages and applies both sides' intents atomically at each stage boundary. The server stores only immutable arena snapshots/results and exposes authenticated defense, opponent, match, settlement, and replay endpoints. The browser adds an arena route that starts and renders server-returned replays without simulating or mutating opponent data.

**Tech Stack:** Browser-native ESM, Node.js ESM, Fastify, PostgreSQL JSONB migrations, `node:assert/strict`, Playwright.
