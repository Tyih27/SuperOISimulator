# Super OI Simulator 玩法改进建议

本文档针对当前版本的两个核心问题提出改进方向：

1. 战力提升手段太少，难以提升战力，只能反复刷关获取资源；
2. 玩法单一，缺乏长期游玩目标。

现状基线（截至 2026-08）：

- 战力提升仅 3 条路径：专项训练（每次 +15～40）、KFC 精力扩充（+50，上限 10,000）、招募新学生（资质区间压制）；
- 玩法仅主线 15 关（重复通关 20% 训练币）、异步竞技场（每日 40 次、胜利 25 训练币）和每日签到；
- `docs/GAME_DESIGN.md` 中已规划但未实现的系统：升级、突破、技能组升级、专题训练场、题目挑战塔、高难题目、竞赛币与竞赛商店、协作解题。

关键架构事实（决定了以下建议的成本）：

- 战斗引擎确定性、不依赖 DOM，任何新玩法只要能构造快照即可复用；
- 关卡是纯数据文件（`src/levels/*.js`），新增关卡和题队几乎零引擎成本；
- 档案为版本化模型并带迁移机制（`src/domain/profile.js`），新增养成字段有成熟的扩展路径；
- 技能组是可扩展目录（`src/data.js` 的 `SKILL_GROUPS`），技能内容数据驱动。

---

## 一、扩充战力提升手段

### 1.1 技能组升级（优先级：最高）

**问题**：技能倍率永远停留在初始值。例如 `SKILL_GROUPS` 中 `planner-burst` 的 `skillMultiplier: 1.5` 写死在数据里，学生培养到后期技能毫无成长。

**方案**：

- 新增道具「技能笔记」，在学生档案页消耗后提升其技能组的常规或爆发技能等级；
- 每级提升技能倍率、辅助效果量或目标数量（具体数值走平衡模拟，参照 `scripts/` 的批量平衡流程）；
- 档案中已有 `skillGroupLevels` 字段（当前恒为 `{ normal: 1, burst: 1 }`），只需让它参与快照构建时的技能参数计算；
- 商店上架「技能笔记」，竞技场胜利也可掉落，形成资源出口。

**理由**：性价比最高的改动——字段已存在、目录已数据化，且直接解决"后期数值全靠专项训练册一条腿走路"的问题。

### 1.2 学生升级 + 突破（优先级：高）

**问题**：GAME_DESIGN.md §7.7 规划的「训练资料 → 经验 → 升级」「突破证明 → 提升等级上限」完全未实现。

**方案**：

- 学生增加 `level` 与 `breakthroughCount` 字段；升级按资质提供五项能力成长系数（高资质成长更快，延续现有分档思路）；
- 达到当前上限后消耗「突破证明」提升上限；不同级别突破证明对应不同突破阶段；
- 主线首次通关奖励改为发放部分「训练资料」与「突破证明」，让推图本身成为养成节奏的一部分。

### 1.3 资质晋升（优先级：中）

**问题**：普通学生永远是普通资质。招募 70% 出普通，抽歪的替补席没有任何长期价值，只能劝退换 1 份材料。

**方案**：

- 允许消耗大量培养材料将学生资质晋升一档（如 普通 → 优秀），能力区间整体上移一档（沿用 `APTITUDE_ABILITY_RANGES` 的相邻区间）；
- 晋升材料主要来自新玩法产出（见第二节），把"养一个普通学生到顶尖"作为零氪玩家的长期追求；
- 注意：晋升需同步更新防守快照重建逻辑，且历史战斗回放不受影响（快照本身不可变）。

### 1.4 协作解题 / 羁绊（优先级：中）

**问题**：队伍搭配只影响站位顺序，缺少组合深度。

**方案**：

- GAME_DESIGN.md §4.8 已预留该机制：特定技能组的学生同时上阵时自动触发额外效果；
- 示例：`planner` + `graphist` 同队时全队专注值获取 +50；三名特定组合同时上阵时开局获得一次免费爆发充能；
- 效果全部走事件日志记录，保证回放一致；
- 它提升的是"搭配策略"而非数值膨胀，与自动战斗定位天然契合。

### 1.5 成就与图鉴被动加成（优先级：低）

**方案**：

- 设置里程碑成就（累计通关数、累计劝退数、竞技场胜场、最高塔层等），达成后给予全队小幅永久加成；
- 同时承担引导功能：用成就奖励引导玩家接触各个新系统。

## 二、丰富玩法、建立长期目标

核心判断：战斗引擎确定 + 关卡纯数据，意味着**新玩法的成本几乎只在入口 UI 和内容数据上**。

### 2.1 题目挑战塔（优先级：最高）

**方案**：

- 无限层数爬塔：每层按难度曲线从题库随机生成题队，通关解锁下一层，失败可重复挑战；
- 记录历史最高层；每周期（周或赛季）重置进度并发放按层结算的奖励；
- 服务端复用现有快照 + 权威结算管线，只需新增"塔层配置生成器"（输入层号与种子，输出关卡配置）。

**价值**：单次实现即获得无限的内容纵深 + 周期性回访理由 + 排行榜素材，是解决"长期没东西玩"的第一杠杆。

### 2.2 专题训练场（优先级：最高）

**方案**：

- 按 GAME_DESIGN.md §8.2 实现：动态规划、图论、数据结构、数学、代码实现各一个训练副本，产出对应专项训练册；
- 每日轮换开放类型（周一图论、周二数学……），每日限次；
- 直接反哺第一节的养成资源缺口，把无目的的"刷关"变成有目标的"刷本"。

### 2.3 竞赛币 + 赛季竞技场（优先级：高）

**问题**：竞技场目前只有"每日 40 次 × 25 训练币"，没有赛季循环，本质是个日常任务。

**方案**：

- 引入 GAME_DESIGN.md §7.4 规划但未实现的竞赛币：按积分段位结算赛季奖励；
- 赛季重置排名（软重置），竞赛商店出售高级突破证明、技能笔记、资质晋升材料等稀有资源；
- 竞技场由此从"每日任务"升级为"长期追求"。

### 2.4 高难题目 / Boss 战（优先级：中）

**方案**：

- 单题超大完成进度条 + 多类型混合难度，限时挑战；
- 按造成的总进度百分比阶梯结算奖励（不要求击杀，鼓励越级挑战）；
- 天然适配竞速与冲榜，可作为赛季活动穿插。

### 2.5 词缀挑战模式（优先级：中）

**方案**：

- 为已通关的主线关卡叠加修饰词缀换取奖励倍率，例如：
  - 「超纲」：题目难度 +30%；
  - 「限时特训」：最大回合数 -2；
  - 「闭卷考试」：禁用辅助技能；
  - 「疲劳作战」：出战学生精力 -30%。
- 复用全部旧关卡数据，近乎白送一套周常玩法，同时给老玩家"重新配队"的理由。

### 2.6 扫荡券（优先级：高，体验修复）

**问题**：重复通关只有 20% 训练币，还必须手动看完整个回放过程，刷关疲劳感强。

**方案**：

- 关卡首次满星通关后解锁扫荡：直接按重复通关奖励结算，跳过战斗播放；
- 扫荡次数计入每日限制（若需要控制产出）；
- 这是纯粹的减负改动，不影响任何经济数值。

## 三、落地顺序建议

```text
第一批（补资源出口 + 长期目标）
  1. 技能组升级
  2. 题目挑战塔
  3. 专题训练场（每日轮换）
  4. 扫荡券

第二批（补养成纵深）
  5. 学生升级 + 突破
  6. 竞赛币 + 赛季竞技场

第三批（补阵容深度）
  7. 资质晋升
  8. 协作解题
  9. 词缀挑战模式
  10. 成就与图鉴加成
```

排序依据：

- 第一批全部依赖现有架构的简单扩展，且立刻缓解"只能刷关"和"没事可做"两个痛点；
- 第二批引入新的档案字段与赛季基础设施，工作量中等但收益持久；
- 第三批涉及更多数值联动（快照重建、平衡回归测试），放在基础循环稳固之后。

## 四、实施注意事项

- 所有新增养成数值必须通过 `npm run simulate:balance` 的批量平衡门槛，并更新 `docs/BALANCE_BASELINE.md` 基线；
- 涉及档案结构的改动必须走版本化迁移（参照既有 profile migration 流程），旧存档学生的缺失字段需要安全默认值；
- 新玩法的战斗一律走服务端权威结算 + 不可变快照 + 事件日志哈希，禁止客户端上报结果；
- 概率类内容（塔层随机、词缀刷新）必须使用固定种子并可由快照复现，保持"相同输入字节一致"的设计原则；
- 每个新系统的奖励产出需纳入货币流水审计（`currency_ledger` / inventory ledger），避免出现绕过流水的资源来源。
