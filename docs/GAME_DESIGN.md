# Super OI Simulator 游戏设计

## 1. 游戏概念

玩家负责培养一支由多名 OI 学生组成的队伍。每场战斗派出 3 名学生，对战多道题目，也可以与其他玩家的三人队伍进行自动对战。

每道题目被视为一个怪物。学生每回合尝试解决题目，提升题目的完成进度；未被解决的题目随后攻击学生，扣除学生精力。

游戏的主要决策是：

- 培养哪些学生，以及提升他们的哪些能力；
- 根据学生的能力和技能组建三人队伍；
- 在战斗前调整学生的出战位置；
- 利用解题技能、辅助技能和专注值爆发时机自动完成战斗。
- 根据对手阵容调整队伍，参加多人竞技和排名。

## 2. 学生

学生是独立的、有姓名的个体，不按职业后缀或固定类型分类。每名学生拥有姓名、资质、五项类型能力、一个个人技能组、总体实力和当前精力。姓名在招生时从姓名库中随机生成，玩家之后可以修改；去除首尾空白后必须为 1～12 个可见字符。姓名只用于识别和展示，不影响数值、技能或战斗结果。这里的“类型”只表示题目和能力所属的知识领域，不表示学生的身份类别。

玩家拥有的学生数量不设上限。学生在账号学生库中长期保留，但每场战斗只能从中选择 3 名不同学生出战，并分别放入 `A1`、`A2`、`A3`。

### 2.1 类型能力

战斗原型暂定以下类型：

- 动态规划；
- 图论；
- 数据结构；
- 数学；
- 代码实现。

类型能力使用数值表示。每名学生在五个类型上都有独立数值；数值不要求形成固定的职业模板，学生之间可以有不同的强弱组合。初始数值由资质对应的区间和招生/配置随机种子共同确定，同一资质的不同学生也不要求拥有完全相同的能力。

战斗原型使用以下资质区间作为平衡基准。每个单元格表示该资质学生在对应类型上的初始水平区间，实际值在区间内取整数；表格是可配置参数，不是成长后的硬上限。相邻资质的区间互不重叠：每一档的下限不低于上一档的上限，高资质在所有类型上全面压制低资质。

| 资质 | 动态规划 | 图论 | 数据结构 | 数学 | 代码实现 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通 | 450～650 | 450～650 | 500～700 | 350～550 | 800～1000 |
| 优秀 | 650～800 | 650～800 | 700～850 | 550～700 | 1000～1150 |
| 稀有 | 800～950 | 800～950 | 850～1000 | 700～850 | 1150～1300 |
| 天才 | 950～1100 | 950～1100 | 1000～1150 | 850～1000 | 1300～1450 |
| 顶尖 | 1100～1300 | 1100～1300 | 1150～1350 | 1000～1200 | 1450～1650 |

同一资质只约束每项能力的取值范围，不要求学生在所有类型上都相同；例如一名“优秀”学生可以擅长动态规划，另一名“优秀”学生可以擅长数学。训练、升级和突破可以使实际能力超过初始区间。

数值统一使用整数。战斗原型中，学生能力和题目难度主要使用百位尺度：普通资质学生常见范围为 `100`～`1000`，顶尖资质学生的初始区间最高可达 `1650`。成长后允许超过该范围，不设置全局硬上限。

资质区间只约束招生时的初始生成；读档校验仅检查能力为非负整数，不设全局硬上限，历史存档中低于新区间下限的学生数值原样保留。

### 2.2 总体实力

总体实力由各项类型能力计算得出，用于展示、队伍比较和关卡推荐。战斗计算直接使用具体类型能力，不直接使用总体实力。

战斗原型可以使用简单平均值：

```text
总体实力 = 所有类型能力之和 / 类型数量
```

### 2.3 精力

精力相当于学生在单场战斗中的生命值。题目攻击会扣除精力。精力降到 0 时，学生退出本场战斗，不能继续做题。

精力与题目进度主要使用千位数。战斗原型中，学生最大精力的建议范围为 `3000`～`10000`，具体由学生数据决定。

精力不会跨战斗保留：

- 每场战斗开始时，所有出战学生均为满精力；
- 战斗中的恢复技能只能恢复本场战斗的精力；
- 战斗结束后，所有学生立即完全恢复到最大精力；
- 玩家不需要在战斗外消耗时间或道具恢复精力。

### 2.4 专注值

专注值是学生独立于精力之外的特殊数值。每次使用常规技能后，专注值会增加；达到上限后，学生下一次行动自动使用爆发技能。

爆发技能使用一次后，专注值清空，需要重新积累。战斗原型中默认专注值上限为 `1000`，常规技能默认增加 `200`。

### 2.5 个人技能组

每名学生恰好引用一个个人技能组。一个技能组固定包含一对技能，这两个技能作为一个不可拆分的组共同配置：

- 常规技能：专注值未达到上限时自动使用；
- 爆发技能：专注值达到上限后自动使用一次，使用后专注值清空。

技能组属于学生，不属于 `A1`、`A2`、`A3` 位置。调整位置只会改变行动顺序和技能的站位相关目标规则，不会替换学生的技能。学生档案保存 `skillGroupId` 和该组的常规/爆发等级；技能内容由可扩展的技能组目录定义。新增技能组只需增加目录内容，再把一个组 ID 分配给学生即可，不需要为位置增加技能字段，也不需要为每名学生复制技能定义。一个学生在同一时间只使用自己所引用的那一组，不能因为站位不同而获得另一组技能。

每个技能还具有一种技能类别：

#### 解题技能

解题技能直接对题目造成影响，推进题目的完成进度。例如：

- 随机攻击一道题目；
- 攻击当前完成度最低的题目；
- 同时攻击多道题目；
- 对单道题目造成更高的完成进度。

#### 辅助技能

辅助技能不直接推进题目，而是改变学生或题目的状态。例如：

- 为精力最低的学生恢复精力；
- 同时为多名学生恢复精力；
- 提高学生的某项能力；
- 降低题目的难度或攻击伤害；
- 使题目跳过下一次行动。

辅助技能的效果量根据施放学生的数值计算。每个技能可以指定一个相关能力和倍率：

```text
效果量 = 基础效果 + 施放学生相关能力 × 技能倍率
```

例如，恢复技能可以使用施放学生的总体实力或某项指定类型能力作为相关数值。常规技能和爆发技能都可以是解题技能，也可以是辅助技能。

学生的常规技能和爆发技能由其所选技能组决定，不在战斗中临时更换。玩家通过选择学生、培养技能组和调整站位构建不同队伍。

### 2.6 学生身份与资质

学生具有不同资质，暂定为：

```text
普通 → 优秀 → 稀有 → 天才 → 顶尖
```

资质影响学生各类型能力的初始区间、成长速度、精力上限和技能强度。当前实现中，成长速度体现为专项训练增量按资质分档（见 7.2）。资质不直接参与战斗公式，而是通过学生的实际数值和技能产生影响。姓名用于识别和展示，不决定能力；同资质学生也可以拥有不同的能力组合和技能配置。

战斗原型的六名样例学生作为学生模板库，新档案创建时从模板库中按档案种子随机选择 3 名不同的模板生成初始学生，姓名随机生成，初始资质统一为“普通”。下表姓名仅作为文档示例，实际运行时可以不同，能力值分别在普通资质的五个区间内配置；后续培养或迁移数据可以使学生拥有其他资质：

| 技术 ID（兼容现有原型） | 姓名 | 资质 |
| --- | --- | --- |
| `planner` | 林澈 | 普通 |
| `graphist` | 周岚 | 普通 |
| `structurer` | 苏砚 | 普通 |
| `mathematician` | 顾言 | 普通 |
| `implementer` | 陈默 | 普通 |
| `supporter` | 许宁 | 普通 |

上述技术 ID 仅用于存档、快照和兼容现有原型，不是学生类别，也不应直接显示给玩家。玩家修改姓名时只更新学生档案的 `name` 字段，不改变技术 ID、资质、能力、技能组、编队或历史战斗快照。后续新增学生沿用“随机姓名 + 资质 + 五项能力 + 个人技能组”的数据结构。

## 3. 题目

每道题目拥有：

- 各个类型的难度；
- 完成进度；
- 最大完成进度。
- 一个题目技能。

难度为 0 表示该题不涉及对应类型。

示例：

```text
题目：树上背包
动态规划难度：800
图论难度：0
数据结构难度：300
数学难度：0
代码实现难度：600
完成进度：0 / 10000
```

完成进度达到最大值时，题目被通过并退出战斗，不再攻击学生。

题目怪也拥有自己的技能。题目技能与学生技能一样由内容数据配置，但它只在题目的 `B` 位行动阶段执行；每道题目可以引用不同的技能 ID、名称、类别、目标规则和数值参数。原型中的题目技能使用 `energyDamage` 效果类型，配置伤害倍率和固定加成；常见目标规则为正对位置优先。题目技能的事件会记录 `skill`、`skillName`、`category` 和目标，客户端不得把缺少名称的题目动作推断为通用攻击。

## 4. 战斗规则

### 4.1 队伍与位置

每场战斗从玩家拥有的学生库中派出恰好 3 名不同学生，并在战斗前放入 `A1`、`A2`、`A3` 三个位置。未出战学生不参与本场战斗，也不会消耗精力或获得战斗内专注值。

一场战斗可以包含多道题目，但场上同时最多存在 3 道活动题目，分别位于 `B1`、`B2`、`B3`。其余题目进入候补队列。活动题目被通过后，下一道候补题目在下一回合开始时补入空位。

```text
学生位置：A1  A2  A3
题目位置：B1  B2  B3
候补题目：B4  B5  B6 ...
```

学生和题目都自动行动，玩家在战斗过程中不手动选择目标或释放技能。`A1`、`A2`、`A3` 只决定出手顺序和站位相关目标选择，绝不决定学生使用的技能。玩家的主要战斗策略来自出战学生、其个人技能组和站位组合。

### 4.2 出手顺序

每回合采用固定的交替出手顺序：

```text
A1 → B1 → A2 → B2 → A3 → B3
```

- 学生精力为 0 时跳过该学生；
- 题目已经通过或当前题目位置为空时跳过该题目；
- 本回合通过的题目立即停止行动；
- 候补题目只在下一回合开始时补位，不会在进入场上后立刻攻击。

### 4.3 自动选择目标

每个技能自带目标规则，学生按照技能描述自动选择目标。解题技能可以采用：

- 随机选择一道活动题目；
- 选择剩余完成度最低的活动题目；
- 选择与自身能力最匹配的活动题目；
- 优先选择正对位置的题目；
- 同时选择多道活动题目。

辅助技能可以采用：

- 选择精力最低的一名或多名学生；
- 选择专注值最低的一名或多名学生；
- 选择指定位置或全体学生；
- 选择难度最高的一道或多道活动题目。

题目技能选择学生目标时，默认优先级为：

```text
正对位置的学生 → 距离最近的存活学生 → 其他存活学生
```

题目的具体技能可以覆盖默认目标规则；例如题目可以配置“正对位置”目标规则、伤害倍率和固定伤害加成。

### 4.4 常规技能

学生的专注值未达到上限时，自动使用其个人技能组中的常规技能。常规技能可以是解题技能，也可以是辅助技能。

常规解题技能示例：

- 随机推进一道题目的完成进度；
- 推进剩余完成度最低的题目；
- 优先推进与自身能力最匹配的题目。

常规辅助技能示例：

- 为精力最低的学生恢复精力；
- 提高一名学生的某项能力；
- 降低一道题目的难度；
- 为一名学生增加专注值。

每次使用常规技能后，施放学生增加固定数量的专注值。

### 4.5 爆发技能

专注值达到上限后，学生在自己的下一次行动自动使用其个人技能组中的爆发技能。

爆发解题技能示例：

- 同时推进多道题目的完成进度；
- 对一道题目造成更高的完成进度；
- 优先攻击难度最高或最接近完成的题目。

爆发辅助技能示例：

- 同时为多名精力最低的学生恢复精力；
- 同时提高全队的能力；
- 同时降低多道题目的难度或攻击伤害；
- 使多道题目暂时无法行动。

爆发技能使用结束后，施放学生的专注值清空。

### 4.6 回合流程

```text
1. 从候补队列向空缺的活动题目位置补入题目
2. 按照 A1 → B1 → A2 → B2 → A3 → B3 进入各行动阶段
3. 在每个阶段开始时检查行动者、专注值和技能类型
4. 根据阶段开始时的快照选择目标并生成效果
5. 统一应用该阶段的进度、精力、专注值和临时状态变化
6. 处理题目通过和学生退出，然后检查胜负条件
7. B3 阶段结束后处理回合末状态和持续时间
8. 进入下一回合
```

### 4.7 结算通则

为保证服务器结算、战斗回放和客户端表现一致，战斗引擎遵循以下规则：

- 玩家对环境战斗按 `A1 → B1 → A2 → B2 → A3 → B3` 顺序结算，每个阶段完成后立即更新战场。
- 多人对战中的同位置行动者使用同一个阶段开始快照同时生成效果，阶段末原子应用。一方在该阶段中被击倒或完成题目，不会取消另一方已经生成的效果。
- 目标并列时默认按位置编号从小到大选择；只有明确标记为随机目标的技能才消耗伪随机数。
- 同一阶段中对同一数值的增减先汇总，再一次性应用并执行上下限。阶段开始前精力已为 0 的学生不能行动、成为治疗目标或被复活。
- 题目进度最低为 0，最高为该题目的最大进度；精力最低为 0，最高为学生的最大精力。
- 题目在战斗开始时确定相关类型。初始难度为 0 的类型不受难度修改影响；其他类型的临时难度最低为 1。
- 临时状态从施加阶段结束后生效。“持续 N 回合”表示状态在当前回合及后续阶段可生效，并在第 `当前回合 + N - 1` 回合结束后移除。
- 同一状态 ID 默认不叠加：保留绝对值更强的效果并刷新持续时间。不同状态 ID 默认相加，技能数据可覆盖该规则。

### 4.8 协作解题

部分学生之间可以具有协作关系。相关学生同时上阵并满足触发条件时，自动产生额外效果，例如追加题目进度、提高全队能力或恢复精力。

协作解题不需要玩家在战斗中手动触发。战斗原型暂不实现，待基础自动战斗稳定后加入。

## 5. 数值计算

以下公式用于战斗原型，数值主要使用百位和千位整数。公式中的基础值、系数和上下限都是可配置参数，不作为后续成长的全局硬上限。计算时只考虑题目难度大于 0 的相关类型。

### 5.1 学生推进题目

```text
能力差距 = 所有相关类型的（学生当前能力 - 题目当前难度）的平均值

基准进度 = round(1000 + 能力差距 × 2)
```

能力高于题目难度时，学生可以更快完成题目；能力低于题目难度时，仍然可以推进，但速度更慢。

### 5.2 解题技能进度

基准进度还需要与技能自身参数结合：

```text
技能进度 = round(基准进度 × 技能倍率 × 目标倍率 + 固定加成)
实际进度 = 题目当前进度 + 技能进度（应用时不超过题目总进度）
```

- 常规单体解题技能可使用 `1.0` 技能倍率和 `1.0` 目标倍率。
- 高进度单体技能主要提高技能倍率，例如 `1.5`。
- 群体技能对每个目标分别计算基准进度，并使用较低的目标倍率，例如 `0.65`。
- `round` 对非负数使用四舍五入，可等价实现为 `floor(数值 + 0.5)`。
- 超出题目剩余进度的部分默认丢弃，不转移给其他题目；特殊技能可在技能数据中明确覆盖。

### 5.3 题目技能伤害

```text
单项能力短板 = max(题目当前难度 - 学生当前能力, 0)

平均能力短板 = 所有相关类型的单项能力短板平均值

精力伤害 = round(500 + 平均能力短板 × 2)
```

题目技能在此基准上应用自身参数：

```text
实际伤害 = round(基准精力伤害 × 伤害倍率 + 固定加成)
```

原型的题目技能效果类型为 `energyDamage`；未声明的效果类型必须由战斗规则显式实现后才能进入内容。学生越不擅长这道题涉及的类型，受到的精力伤害越高。

### 5.4 计算示例

```text
题目：动态规划难度 800，代码实现难度 600
学生：动态规划能力 600，代码实现能力 700

能力差距 = ((600 - 800) + (700 - 600)) / 2 = -50
基准进度 = 1000 + (-50 × 2) = 900
常规单体技能进度 = round(900 × 1.0 × 1.0 + 0) = 900

平均能力短板 = (max(800 - 600, 0) + max(600 - 700, 0)) / 2 = 100
精力伤害 = 500 + 100 × 2 = 700
```

### 5.5 辅助技能效果量

辅助技能的恢复、增益和削弱效果使用技能自身的基础值，并根据施放学生的相关数值成长：

```text
效果量 = round(基础效果 + 相关能力 × 技能倍率)
```

例如，某学生使用“恢复精力”技能：

```text
基础恢复：1000
学生总体实力：800
技能倍率：0.2
恢复量 = 1000 + 800 × 0.2 = 1160
```

群体辅助技能可以使用相同公式作用于多个目标，也可以为群体技能设置较低的技能倍率。每个技能分别配置最小值和最大值，不使用全局统一的小数值上限。

### 5.6 专注值示例

```text
专注值上限：1000
常规技能使用一次增加：200
使用常规技能 5 次后达到专注值上限
下一回合自动使用爆发技能
爆发技能使用后清空为 0
```

## 6. 胜负条件

游戏支持两种关卡目标。

### 6.1 通过数量

玩家需要在规定回合内通过指定数量的题目。

```text
示例：10 回合内通过 5 道题
```

### 6.2 全部通过

玩家需要在规定回合内通过关卡中的全部题目。

### 6.3 失败

满足以下任意条件时战斗失败：

- 3 名学生的精力全部降到 0；
- 回合数耗尽，仍未达到关卡目标。

### 6.4 多人对战判定

多人对战中，双方分别挑战内容相同的镜像题目队列。所有终局判定只在当前同步阶段完整结算后执行，不使用单方的中间状态判断胜负。

- 若只有一方在该阶段达成本场要求的全部题目，该方立即获胜；即使同一阶段学生全部退出，题目完成仍然优先。
- 若双方同一阶段完成全部题目，比较双方队伍该阶段结束时的剩余精力总和；仍然相同时判定为平局。
- 若任一方未完成全部题目但该方所有上阵学生均已退出，则该方负。若双方在同一阶段同时退出，转入下述比分规则。

达到最大回合数且双方都未触发终局时，依次比较：

```text
通过题目数量
→ 所有未通过题目的完成率之和（完成进度 / 最大进度）
→ 队伍剩余精力总和
→ 达成当前成绩所用的最后一个行动阶段（回合，阶段）
```

前三项数值更大者胜，最后一项的行动阶段更早者胜。所有项目仍然相同时判定为平局。

## 7. 学生获取、道具与养成

### 7.1 学生获取

玩家可以通过招生、主线奖励、活动任务和特殊挑战获得学生。新学生的姓名由姓名库随机生成，玩家可以在学生详情中修改姓名；改名不改变学生的资质、能力、技能或养成进度。招生可以设置保底次数，但具体概率、次数和资源消耗在数值设计阶段确定。

当前单机纵切片的招募参数：训练币商店可用 300 训练币购买 1 个招募权（招募券）；每次招募按“普通 70%、优秀 20%、稀有 8%、天才 1.9%、顶尖 0.1%”进行加权抽取。连续 29 次未获得天才或顶尖后，第 30 次招募强制获得天才；获得天才或顶尖后保底计数清零。保底计数保存在玩家档案中，由服务端事务更新。

重复获取的招募学生不会自动转化；玩家可以在学生详情中主动“劝退”学生，获得学生培养材料，用于突破或技能组升级。所有学生（包括初始学生）只要不在当前编队中都可以劝退；当前编队中的学生必须先换下场才能劝退。替补席按总体水平降序排列，并提供“批量劝退”：面板按资质统计替补数量并支持一键全选/取消某资质的学生，点击学生卡片任意位置即可勾选；一次批量劝退时每名被劝退学生各获得 1 份学生培养材料（同一事务内完成）；若所选包含稀有及以上资质学生，界面会给出提示并要求再次点击确认才会执行。替换学生的候选列表同样按总体水平降序排列。

### 7.2 基础养成

单机纵切片保留四种直接养成方式：

- 升级：提高总体基础数值；
- 突破：提高等级上限和成长幅度；
- 技能组升级：提高所选技能组中常规或爆发技能的倍率、效果量或目标数量；
- 专项训练：提高一种类型能力。当前实现中，每次强化按学生资质增加对应增量——普通 +15、优秀 +20、稀有 +25、天才 +30、顶尖 +40；优先消耗对应能力的专项训练册且不收取训练币，没有对应训练册时可消耗 1 份学生培养材料并支付 100 训练币。

强化必须同时满足资源条件：使用学生培养材料时训练币不少于 100（使用专项训练册免费）。学生能力不设上限。资源不足时操作失败，材料、训练币、能力值和档案版本均不改变。成功后服务端返回能力前后值并持久化新的能力值。精力在每场战斗结束后自动完全恢复，不属于战斗外养成内容。

### 7.3 暂缓的养成系统

装备、天赋树、随机洗练、代数和外观等系统暂不进入首个异步多人版本，避免在核心自动战斗验证前增加过多养成层级。

### 7.4 货币

完整的单机与多人循环使用三种主要货币。单机纵切片先实现训练币和招生券，竞赛币随首个异步多人版本加入：

| 货币 | 主要来源 | 主要用途 |
| --- | --- | --- |
| 训练币 | 主线关卡、日常任务、战斗结算 | 购买基础培养道具、支付升级消耗 |
| 竞赛币 | 异步竞技场、赛季结算、排名奖励 | 在竞赛商店购买稀有培养道具 |
| 招生券 | 主线奖励、活动、成就 | 招募新学生 |

货币只存在于玩家账号中，不进入单场战斗，也不能被其他玩家夺取。

### 7.5 培养道具

玩家在商店购买培养道具，再到学生养成界面使用。单机纵切片道具包括：

| 道具 | 用途 |
| --- | --- |
| 训练资料 | 为学生增加经验并提升等级 |
| 突破证明 | 学生达到等级上限后进行突破 |
| 技能笔记 | 提升所选技能组中的常规技能或爆发技能等级 |
| 专项训练册 | 提高动态规划、图论、数据结构、数学或代码实现能力 |
| 学生培养材料 | 在没有对应专项训练册时，替代训练册完成一次学生强化 |

不同级别的道具可以提供不同数量的经验或升级进度。专项训练册按能力类型区分，不能用于其他类型能力；学生培养材料不绑定能力类型，但每次只能消耗 1 份，并按学生资质增加目标能力（普通 +15 至顶尖 +40）。

### 7.6 商店

商店分为：

- 基础商店：使用训练币购买训练资料、低级突破证明和专项训练册；
- 竞赛商店：使用竞赛币购买高级突破证明、技能笔记和高级专项训练册；
- 招生商店：使用招生券招募学生。

单机纵切片实现基础商店和招生商店，竞赛商店随首个异步多人版本加入。

商店道具不设购买次数上限。商店只出售道具，不直接出售永久属性，学生升级仍然需要在养成界面完成。

### 7.7 升级流程

```text
完成关卡或多人竞技
→ 获得货币
→ 在商店购买培养道具
→ 选择需要培养的学生
→ 消耗道具和训练币
→ 提升等级、突破、技能或专项能力
```

## 8. 游戏模式

### 8.1 主线关卡

主要推进玩法。玩家挑战由多道题目组成的关卡，获得训练币、培养道具和招生券。

主线之外提供「额外关卡」（如第 2 章「竞赛进阶」）：不占用主线编号，在主线页面单独分区展示；通关主线终关后按顺序逐个解锁，题目难度显著高于主线，推荐以队伍总战力衡量挑战门槛。

### 8.2 专题训练场

不同训练场对应动态规划、图论、数据结构、数学和代码实现等类型，主要产出专项训练材料。

### 8.3 题目挑战塔

连续挑战逐渐变难的题目队伍，根据到达层数获得奖励。

### 8.4 多人模拟赛与排行榜

两名玩家分别派出三人队伍，挑战内容相同的镜像题目队列。双方队伍自动行动，并可以通过辅助技能强化己方或削弱对方。战斗结果计入竞技排名，并产出竞赛币和赛季奖励。

### 8.5 高难题目

设置拥有较高完成进度和多种题型难度的高难题目，根据队伍造成的总进度或是否完成进行奖励结算。

主线关卡在单机纵切片实现，异步竞技场在首个异步多人版本实现。专题训练场、挑战塔、实时匹配和高难题目在基础自动战斗与养成循环稳定后逐步加入。

## 9. 多人对战

### 9.1 基础形式

多人对战采用三人队伍对三人队伍的自动模拟赛。双方不会手动操作学生，而是在战斗前选择阵容和站位。

双方各自拥有一份内容、顺序和初始状态完全相同的镜像题目队列。己方解题技能只推进己方题目，题目也只攻击对应一方的学生。

为避免先手优势，双方相同位置同时结算：

```text
玩家1-A1 与 玩家2-A1 同时行动
→ 双方 B1 同时行动
→ 双方 A2 同时行动
→ 双方 B2 同时行动
→ 双方 A3 同时行动
→ 双方 B3 同时行动
```

同一阶段产生的效果在该阶段结束后统一生效。

### 9.2 辅助技能互动

辅助技能根据技能描述确定作用范围：

- 己方学生目标：恢复精力、提高能力、增加专注值；
- 对方学生目标：降低能力、减少专注值、增加受到的精力伤害；
- 题目目标：降低己方题目难度，或临时提高对方题目难度；
- 全场目标：同时影响双方或全部活动题目。

所有技能自动选择目标。对方技能不能直接修改永久养成数值，效果只在当前对战中持续。

### 9.3 异步竞技场

首个异步多人版本采用异步竞技场：

1. 玩家设置自己的防守队伍和站位；
2. 服务器保存该队伍的学生数值与技能快照；
3. 进攻玩家选择对手后开始自动战斗；
4. 服务器使用固定随机种子计算战斗结果；
5. 双方可以查看战斗结果和回放；
6. 胜负影响积分、排名和赛季奖励；进攻方获胜时获得 25 训练币，平局或进攻失败不获得该奖励。

异步竞技场不要求双方同时在线，适合先验证阵容搭配、技能互动和排行榜循环。进攻方胜利奖励由服务端事务同时写入货币流水和玩家档案；客户端结算后重新读取档案，避免只显示奖励提示而不更新余额。

### 9.4 战斗快照与回放

异步竞技场使用版本化的战斗记录。服务器在开战时固化以下数据：

- 战斗引擎版本和数值配置版本；
- 双方学生的实际能力、精力、专注值、个人技能组引用和站位快照，以及对应的技能组目录快照；
- 题目队列、每道题目的最大进度、初始难度、题目技能和初始状态；
- 伪随机数算法标识和固定种子；
- 按结算顺序排列的事件日志，以及事件日志哈希。

服务器以事件日志作为历史战斗的回放源，客户端播放快照和事件，不根据当前代码重新计算历史战斗。服务器可用快照、种子和引擎版本重新计算作为审计手段，计算结果的事件日志哈希必须一致。

### 9.5 实时对战

后续可以加入好友房间和实时匹配。实时对战仍然自动进行，服务器负责同步回合、随机数和战斗结果，玩家只在开战前调整队伍。

## 10. 核心循环

```text
获取学生
→ 使用初始资源培养学生
→ 选择三人队伍并调整站位
→ 自动挑战题目关卡
→ 获得货币和培养道具
→ 在商店购买所需道具
→ 强化学生并挑战更高关卡
```

玩家的主要操作集中在战斗前。战斗过程负责展示学生个人技能组、题目技能、爆发技能和队伍搭配产生的结果。

多人竞技循环为：

```text
调整防守队伍
→ 挑战其他玩家
→ 自动结算镜像题目战斗
→ 获得竞技积分和竞赛币
→ 购买稀有培养道具
→ 培养学生并优化阵容
```

## 11. 原型与版本范围

### 11.1 战斗原型

战斗原型只用于验证自动战斗、编队和站位是否形成有意义的决策。该阶段包含：

- 初始提供 3 名随机抽取的模板学生（有姓名、普通资质、不同五项能力组合和个人技能组配置）；能力值按普通资质区间配置，不使用职业后缀作为学生类别或展示名；
- 学生库数量不设上限；每场从中选择 1～3 名不同学生上阵，并调整 `A1`、`A2`、`A3` 站位，允许留空部分站位；
- 5 种类型能力；
- 3 个活动题目位置和候补题目队列；
- 固定交替出手顺序、自动选择目标和自动释放技能；
- 可扩展的个人技能组（各含常规/爆发技能）、解题技能、辅助技能、题目技能以及本文定义的大数值公式；
- 一个固定题目队列、一个关卡目标和可追溯的战斗事件日志。

战斗原型不包含货币、招生、商店、账号、匹配和排行榜。

### 11.2 单机纵切片

基于战斗原型加入可完成的单机循环：

- 版本化账号档案模型，包含学生永久属性、背包、货币、已解锁关卡和编队配置；每场战斗必须从档案生成独立的不可变初始快照；
- 主线关卡、战斗结算、账号数据持久化；
- 账号注册与账号密码登录。服务端仅保存密码哈希，不保存或回传明文密码；
- 已登录账号的学生库、养成进度、货币、背包、关卡进度和编队配置均持久化保存，并在其他设备登录后恢复；
- 首批实现 3 至 5 个主线关卡，并覆盖“通过指定数量”和“全部通过”两种目标；
- 先实现专项训练作为首个可验证的养成操作，再逐步加入升级、突破和技能升级；
- 升级、突破、技能升级和专项训练；
- 训练币、招生券和培养道具；
- 基础商店、道具背包、购买限制和道具消耗；
- 为开发与数值平衡提供批量战斗模拟工具，统计不同阵容、站位和随机种子的胜率、平均回合数与技能使用率；

### 11.3 首个异步多人版本

单机纵切片稳定后再加入：

- 异步竞技场和防守队伍设置；
- 对手匹配、竞技积分、排行榜和赛季奖励；
- 服务器权威战斗结算；
- 版本化学生快照、题目队列、固定伪随机种子和事件日志回放；
- 竞赛币、竞赛商店和基础的防作弊校验。

首个异步多人版本暂不实现协作解题、实时匹配、好友房间、挂机收益、装备、随机事件和学生关系系统。
